=====================
Writing documentation
=====================

Where documentation goes
------------------------

- **Code reference** (this site): docstrings of the plugins and functions. The reference pages are generated by
  ``docs/source/conf.py`` at every build and are not kept in git: the API (``sphinx-apidoc``) and the data-structure
  page (``docs/source/build_data_structure_doc.py``: columns from ``st.data_info``, dependency graphs, options). A new
  plugin appears there automatically once it is registered in the default context; give it a docstring and
  column comments in its dtype.
- **How to use and operate** (processing on STBC, corrections, the event format, analysis): the XAMS handbook
  (repository ``XAMS-nikhef/xams-handbook``), which is the canonical documentation.
- **Explainers as PDF**: ``docs/notes`` (``make_amstrax_note.py``), regenerated after a change to plugins or
  contexts.

Build
-----

Read the Docs builds https://amstrax.readthedocs.io from master (``.readthedocs.yaml``: Python 3.12, graphviz,
``extra_requirements/requirements-docs.txt`` and ``pip install .``). To build locally, in an environment with
amstrax and those requirements (and the ``dot`` program of graphviz):

.. code-block:: bash

    cd docs
    make html          # output in docs/build/html; set AMSTRAX_DOCS_SKIP_DATASTRUCTURE=1 to skip the slow page
